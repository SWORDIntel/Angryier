# Sustained, contract-partitioned symbolic exploration

**Shipped:** the host-native distributed CLI and Rust API run a pinned ELF or modeled PE root across 1, 2 or 4 worker processes. One coordinator verifies returned work and owns the checkpoint and WAL. Local Lua `angry.sustained` v1/v2 is a separate interface, not a distributed policy. See the [operator guide](../guides/distributed-campaigns.md) and [bounded verification record](sustained-exploration-verification.md).

    ## Original baseline and design rationale (historical)

- `SymbolicSession::run_with_policy` bounds each run by total steps and a wall deadline; when live states exceed `max_states`, it removes the excess into `dead` and increments `pruned_states` (`crates/angryier-runtime/src/lib.rs:9146-9229`). That is appropriate for today's bounded search but **not** lossless long exploration. Its report records remaining live states, yet the ordinary Lua report describes just one diagnostic frontier (`crates/angryier-runtime/src/script/mod.rs:770-785,810-895`).
- The Lua option parser already selects `find`, `avoid`, `steps`, `states`, `timeout_secs`, `exploration`, `search` and solver policy (`crates/angryier-runtime/src/script/mod.rs:601-654`). A prepared image runs multiple *independent*, fresh campaigns concurrently with ordered Lua reports, not one continuing path frontier (`crates/angryier-runtime/src/script/prepared.rs:614-689`). Reuse its template and worker-safe campaign construction where applicable, not the batch API as a substitute for frontier ownership.
- Branch decisions retain PC, targets, constraint-prefix length, dynamic visit index and trace fingerprint (`crates/angryier-runtime/src/script/mod.rs:1069-1086`), but the engine **silently removes the oldest decision after 64 entries** (`crates/angryier-runtime/src/lib.rs:6488-6492,6640-6646`) and **silently removes the oldest trace PC after 4,096 entries** (`crates/angryier-runtime/src/lib.rs:235,748-753`), making later visit indices inexact. Both fixed history truncations must be removed for this feature, including from legacy paths if they share these structures. The fingerprint is diagnostic, **not** a collision-resistant identity or replay proof. Concrete alternate-branch replay checks path context (`crates/angryier-runtime/src/lib.rs:9931-9947`). Merge code deliberately discards branch-history prefix indices when it rewrites constraints (`crates/angryier-runtime/src/lib.rs:9298-9305`); contract mode must never silently merge distinct owned paths and then claim each was explored.
- `angryier-ledger` and `angryier-qihse` currently expose **in-memory** implementations (`crates/angryier-ledger/src/lib.rs:67-95`; `crates/angryier-qihse/src/lib.rs:55-65`). `angryier-distribution::InMemoryWorkCodec` explicitly lacks network framing (`crates/angryier-distribution/src/lib.rs:69-75`). None is already a durable frontier store or working cluster transport. `scripts/lua/bulk_resolve.lua` is useful precedent for job-level tombstones, not a per-branch durable queue.

## Contract and engine invariants (freeze before implementation)

1. **Campaign identity:** a versioned manifest pins binary bytes/digest, architecture/entry, semantic engine version/profile, Lua policy/script digest, all seeded inputs and external `load_mem`/stub data, solver/fidelity policy, and immutable limits. Reject mismatched or missing inputs on resume or another host. A changed binary, model or relaxation creates a *new* campaign, never a silent continuation. Identity uses a collision-resistant content digest, not `state.id`, a virtual address, or the 64-bit trace fingerprint alone.
2. **Work identity and disjointness:** a work unit names the campaign plus an ordered prefix of *dynamic* symbolic branch decisions (branch-site identity, exact visit/iteration index, successor and replay context). At a verified fork with prefix `P`, replace its **unexplored remainder** with disjoint `P·0` and `P·1`; a parent may be retired only after both child outcomes are recorded. A prefix-free set of owned subtrees prevents two workers from accepting the same path. `C ∧ b` and `C ∧ ¬b` partition the parent's constraint space; this alone does **not** prove either side SAT or that execution outside the modeled environment is complete. Non-symbolic/control/environment forks require an explicit, separately identified partition rule or remain unresolved.
3. **Replay and merges:** first milestone uses root replay from pinned inputs and branch choices; verify the full dynamic prefix and its symbolic context before continuing. On mismatch, stop that unit with evidence; never silently redirect to a nearby PC. Remove the 64-decision branch-history and 4,096-PC trace truncations instead of hiding them behind a second contract identity; if retention exceeds a configured budget, spill/defer or explicitly stop, **never trim either prefix**. Replace the old capped-trace test with >4,096-step exact-visit coverage and add >64-decision history/replay tests. Keep solver contexts thread/host-local. In contract mode, disable cross-owner and provenance-destroying merges until there is a proved disjunctive-ownership representation; leave legacy merging unchanged. Loops need exact visit ordinals and explicit per-path step/depth/iteration ceilings.
4. **No silent loss:** distinguish *live in memory* from *deferred on disk*. At an active-state limit, defer a reproducible job instead of pushing a state into `dead`. On time, step, RAM/disk, solver or per-path limit, preserve the remainder as `deferred` or `blocked` with a reason; only an intentional `avoid` rule is `excluded_by_policy`. If a frontier cannot be durably recorded, fail closed and do not report the subtree complete. Never reinterpret `UNKNOWN`, timeout, under-constrained behavior or semantic debt as UNSAT.
5. **Completion and rebalancing:** the scoped campaign is `complete_within_declared_bounds` only after every owned work unit has an accepted terminal/excluded/solver-proven-infeasible disposition and none is queued, leased, deferred, unknown or failed. Report `partial`, `paused`, `blocked` or `failed` otherwise, with counts and exact reasons. Local ownership needs no network; a later cluster update is epoch/fence based and transfers coarse subtrees, not a thread or solver on every fork. At most one epoch may **accept** results for a work unit; crash/retry may redo computation, so do not claim physical exactly-once execution.

### Suggested versioned records

`CampaignManifest { schema_version, campaign_digest, binary_digest, input_artifact_digests, engine_semantics, script_digest, initial_state, limits, fidelity }`; `WorkUnit { campaign_digest, contract_epoch, prefix, replay_descriptor, status, owner, attempt }`; `Transition { parent, child_0, child_1, solver_disposition, replay_evidence, semantic_debt }`; `Finding { path_id, blocks, edges, branch_predicates, witness_digest?, replay_status, provenance, fidelity }`. Bound record size, trace retention and graph cardinality. Content hashes identify immutable records; ledger revision/epoch fences mutable disposition. Decide a canonical encoding and test round trips, corruption and version rejection before shipping. Do not use raw arena expression IDs or Lua floating-point addresses as portable identity (Lua high-half addresses use exact `_hex` values; `docs/LUA_API.md:86-97`).

## Measurable gates and execution policy

- **M1 (local correctness):** on finite synthetic binaries, one-worker contract exploration matches an independently enumerated bounded path set; 2/4 local workers give the same accepted path IDs and evidence regardless of scheduling. No deferred state is counted as explored. Merge/convergent/loop fixtures, forced solver `UNKNOWN`, unsupported instruction, under-constrained memory and replay mismatch exercise all terminal/partial classifications. Current Lua tests (`crates/angryier-runtime/tests/lua_api.rs:766-820,1075-1121`) and prepared batch parity (`tests/prepared_api.rs:201-250`) still pass.
- **M2 (restart/durability):** interrupt mid-fork and mid-result, resume with identical manifests, observe no missing or duplicate **accepted** path IDs, and reject a changed binary/script/semantics. Bound live RAM, queue/disk bytes, trace storage, per-query solver time, path depth, loop iterations and total run time. When storage is exhausted, fail closed with recoverable state rather than claim completion.
- **M3 (useful analysis):** machine-readable summary includes unique explored/feasible/UNSAT/unknown/deferred/failed/excluded paths, branch and block/edge coverage, graph of verified dynamic flow, witness/replay/debt counts and remaining frontier. Require graph edges with provenance, not just a giant trace or a single `frontier`. Compare compile/engine/runtime versions and checksum-pinned outputs for reproducibility. Compact human report first; full raw artifacts stay bounded and queryable.
- **M4 (performance):** measure useful **unique accepted paths and verified edges per wall-hour**, solver time, replay cost, RSS, disk bytes and idle time against legacy bounded campaigns on *the same* fixture and policy. Report overhead and lack of scaling honestly. Existing `docs/BENCHMARKING.md` and `scripts/gate_report.sh` can guide measurement, but their old gate results do not establish this feature's speedup.
- **M5 (HPC, only after M1–M4):** first run the exact same manifest on a single PC using multiple local workers; then native builds on the three hosts with an epoch contract covering disjoint subtrees. Compare combined unique verified work vs best single-host run under recorded resource ceilings. The coordinator publishes coarse contract updates; worker fork throughput must not depend on controller round trips. A failed/partitioned host leaves a visible unaccepted or reclaimable frontier, not a fabricated complete report.

## Explicit exclusions and failure language

No claim of literal exhaustive coverage of arbitrary binaries, no silent promotion of guessed/relaxed execution to proven behavior, no global solver migration, no automatic decompilation or patch correctness proof, and no requirement to run Docker/Slurm. Some programs have unbounded paths or undecidable reachability. **Completion always names the exact declared limits and fidelity model.** The initial work is a local, lossless *bounded* explorer and honest flow evidence; networking, eBPF optimizations, solver portfolios and live-state snapshots are later, evidence-driven options, not prerequisites.
