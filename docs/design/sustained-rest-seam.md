# Sustained exploration: implementation boundaries

    The [original design](sustained-exploration-plan.md) proposed the interfaces below. The type sketches and ordered gates following this section are historical design criteria, not the current API. See the [operator guide](../guides/distributed-campaigns.md) for supported commands and [verification record](sustained-exploration-verification.md) for measured fixtures.

    ## Current contracts and non-claims

    - The campaign manifest pins image, build, replay semantics and limits. Dynamic branch prefixes partition work; a structurally valid split alone proves neither feasibility nor execution. Workers return claims; the coordinator independently replays the subtree before accepting evidence.
    - The single writer commits ownership and evidence together. The checkpoint and append-only WAL are authoritative; JSONL is rebuilt from accepted events. A restart can requeue interrupted grants but does not retry deferred paths. Verified witnesses require concrete replay in the pinned model.
    - Distributed callers use `angryier-campaign` or the [Rust API example](../../crates/angryier-campaign/examples/rust_api.rs) with 1, 2 or 4 peers. Authenticated loopback TCP needs an external encrypted tunnel between hosts. PE-driver replay includes synthetic loader state, not a live Windows environment.
    - Local Lua v1 (`fork-all/v1`) observes find/avoid; v2 (`rank-targets/v1`) ranks work and can exclude exact proof-bound avoid targets. Neither policy is a distributed CLI flag or Rust pool option.

## Frozen shared record boundaries

The names below are proposed **handoff types**, not claims that they already compile. `Digest` means a domain-separated canonical SHA-256 of length-delimited versioned bytes, not a PC or `StateId`. No module outside the single coordinator writes an ownership transition.

| Owner and proposed interface | Inputs / result / obligation |
| --- | --- |
| `angryier-distribution::contracts`: `WorkKey { campaign_digest, contract_epoch, prefix }`, `AttemptToken { work_key, attempt, ownership_epoch, owner_id }` | Keep v1 `WorkUnit` identity and prefix-free, complementary-fork validation. Canonicalize/sort before hashing; reject duplicate/ancestor/inconsistent fork contexts. `ownership_epoch` is a monotonically increasing **per-work grant generation** separate from the campaign contract epoch; a former worker cannot publish under a new grant. |
| `angryier-runtime`: `AdvanceRequest { reservation: AttemptToken, replay: ReplayDescriptor, limits, objective_policy } -> AdvanceOutcome { transition, evidence_delta, witness_candidates, cost }` | Run only a fresh pinned root. Check every recorded dynamic prefix/solver context; return explicit terminal, split with both child dispositions, excluded, deferred, unknown, failed or replay mismatch. Never let a worker set ledger `Completed` directly. Solver SAT is not a concrete witness; UNSAT is scoped to the exact query, constraints and solver outcome. Preserve exact history or stop/defer when bounded. |
| `angryier-provenance`: `EvidenceDelta { scope: EvidenceScope, work_key, attempt, sequence, paths, frontier_changes, solver_records, witness_refs, debt }`; `EvidenceSnapshot { schema_version, scope, committed_generation, paths, frontier, aggregates, closure }` | A delta is keyed by **path ID plus exact attempt and event sequence**, not PC; deduplicate retries by event identity and reject conflicting payloads. Aggregate *cumulative accepted* per-path dynamic blocks/edges and separately label static inference and solver-infeasible edges. Keep exact path/provenance/fidelity and observed trace context; report frontier from authoritative ledger state. Bound item count, bytes and query size; overflow blocks acceptance rather than truncating evidence. |
| `angryier-ledger`: `commit_outcome(token, transition, evidence_delta, witness_refs) -> CommittedGeneration` and `read_snapshot(generation) -> (ownership, evidence)` | The ledger is the authoritative linearization point for ownership, status, fence and evidence reference. Stage/checksum/fsync bounded evidence and witness artifacts first, then atomically commit ownership transition **and their content digests** in the ledger snapshot/journal, then fsync parent directory. Unreferenced staged blobs are garbage, never accepted evidence. Recovery verifies references/digests; missing/corrupt data blocks the subtree/campaign and never reports completion. If storage cannot provide these guarantees, embed the bounded evidence in the same atomic snapshot instead. Do not treat a second independent atomic rename as a transaction. |
| `angryier-runtime` concrete replay adapter: `WitnessCandidate { work_key, model_query_digest, canonical_input_bytes, expected_successor, expected_path_context } -> WitnessResult { input_digest, replay_trace_digest?, matched_prefix, reached_target?, status, failure }` | Materialize only supported entry-time symbolic register/memory/argv bytes and pinned external artifacts into a **fresh** executable root. Concrete replay must independently check full branch prefix, visit/target, relevant path/trace, final target and absence of semantic debt. Store bytes under a bounded content digest before referencing them. `Verified` is issued **only** after replay really ran and matched; unsupported sources, partial model, SAT-only, timeout, mismatch or absent bytes remain candidate/not-checked/error, never verified. `WitnessEvidence` currently carries only digest/status and must not be interpreted as proof of that operation. |

Use a versioned on-disk evidence schema distinct from `EVIDENCE_SCHEMA_VERSION = 1` (in-memory shapes). Encode explicit maximum lengths/counts and canonical byte ordering. On reopen validate the entire manifest/artifact set, snapshot generation, every live leaf's prefix-free relation, all referenced evidence/witness digests, per-path status and frontier reconciliation before accepting a reservation. Treat impossible contradictions (e.g. the same observed edge also solver-infeasible in the same context) as corruption, not a warning. Aggregation by `(from_pc,to_pc)` is a **view** only; retain distinct dynamic visits and path IDs underneath. Closure requires all ledger leaves accepted terminal/excluded/proven infeasible and durable evidence for every resolved leaf; queued, active, deferred, unknown, failed, stale or unaccounted evidence force partial/blocked/failed. Do not emit aggregate `replay_verified_witnesses` from a status value without replay provenance.

### Deterministic single-PC multi-worker ownership

One coordinator owns the ledger and accepted evidence; N host-native worker processes/threads receive immutable `GrantedWork { WorkKey, AttemptToken, ReplayDescriptor, artifact_digest_set, deadline }` and return bounded `AdvanceOutcome`. The coordinator chooses the **lowest canonical work-key order** for admission, records a durable grant with owner/attempt/generation, and dispatches disjoint prefix-free subtrees. Execution finish order may differ; accepted path IDs, disposition and canonical sorted evidence must not. If result ordering affects ranking, persist a deterministic priority key and tie-break by work key; never use lock timing or worker identity for meaning. Worker computation may fork locally with no coordinator RPC on every branch; durable splits are submitted atomically at coarse boundaries. No two accepted live grants overlap. `reserve` v1's single `Active` slot/attempt is insufficient for concurrent owner fencing; keep v1 snapshots readable only under the old single-writer mode or migrate explicitly under lock.

Every worker result must match campaign digest, binary/semantics/solver/policy, active contract epoch, work prefix, owner, grant generation, attempt and an idempotency key `(work_key, grant, sequence, outcome_digest)` before the coordinator commits it. On crash/restart, expired grant or disconnection, durably advance that work's generation and requeue it **without** dropping previous accepted descendants; late responses are rejected even if their numeric attempt matches. Timeout never means a path completed. A split's two complementary children and evidence references commit together; failures before commit leave/recover the parent, failures after commit recover the children. Cross-path state merging is disabled unless a separately proven ownership-preserving merge contract is designed.

### Lua analyst objectives and policy (after durable evidence)

Introduce a **bounded declarative** v2 objective/policy value, not acceptance of arbitrary script bytes. Parse `find`, `avoid`, search mode, ranking weights/tie-break, budgets and exclusions into a canonical versioned policy record; hash **the actual parsed semantics** in the campaign manifest. Reject unknown keys, NaN/nonfinite weights, duplicate/contradictory targets, mutable Lua tables on resume/advance, unsupported callbacks or unsupported input/stub application. Explicitly distinguish `avoid` as `exclude_on_observed_hit` (a durable `ExcludedByPolicy` leaf with trace/policy evidence), versus `deprioritize` (no exclusion); make `find` an observed target hit and a ranking objective, not a completeness claim or automatic termination of unrelated leaves. Rank queued candidate subtrees deterministically using a documented tuple such as `(policy priority, bounded CFG distance to find, path depth, canonical work key)`; unknown CFG distance ranks last, never fabricates reachability. Tie-break and queue order survive restart; report target hits cumulative across committed evidence and distinguish observed, static inferred and solver-infeasible. A policy that changes ownership/dispositions starts a new campaign. Keep v1 `fork-all/v1` and observational targets exactly as they are; do not relabel observational data as active policy or pretend to execute `script = "angry.sustained/v1"`.

### Later authenticated TCP / native host boundary

Only after local fences and evidence/replay gates, define a separate bounded transport `Frame { magic, transport_version, type, payload_len, request_id, campaign_digest, grant_generation, checksum, payload }` over authenticated, confidential channels (mutual TLS or equivalently pinned peer keys; explicit allowlist identities and host role). Require a version handshake and pinned native worker build/semantic/solver/architecture and complete artifact digests before any grant. Check length and negotiated caps **before allocation**, canonical decode, checksums, authentication and campaign/fence before dispatch. Set frame and decompressed-size caps, read/write/idle deadlines, backpressure and bounded outstanding grants; reject unknown versions/types/fields, oversized/truncated frames, replayed request IDs, unauthenticated hosts, wrong build or stale epochs. Checksums detect corruption; they are not authentication. No raw Lua bytecode, arbitrary filesystem paths, or legacy `InMemoryWorkCodec` frames on the wire. Binary and input bytes use authenticated digest-checked content transfer with explicit quotas; never trust a claimed digest without verifying supplied bytes.

A coordinator executable owns the ledger, recovery, policy ranking, grant lifecycle and accepted evidence. A host-native worker executable opens **only a granted subtree** using an independently validated manifest and returns bounded results and witnessed artifact references; it does not mutate shared ledger files. Allow one-PC coordinator plus 2/4 native workers with the same protocol and deterministic accepted records before using multiple hosts. On partition, no split-brain writes: fenced worker may continue private computation but its results are unaccepted until the coordinator revalidates grant; a new generation invalidates it. Resume/handoff publishes only coarse subtrees, not a solver state or per-branch RPC. Reject incompatible versions/builds rather than silently downgrading correctness.

## Ordered gates and test evidence required before claiming each one

1. **Durable cumulative evidence.** Extend ledger transaction/reference schema and provenance aggregation; forced kill before/after artifact fsync/rename and snapshot fsync, torn/corrupt/missing artifact, disk-full/limit and retry duplicates. Advance twice, reopen, then assert cumulative paths, observed edges, exact frontier and closure agree with ledger. A v1 snapshot migration/rejection test must make old data handling explicit. No evidence commit without an ownership commit.
2. **Concrete input witness.** On a real finite ELF with native solver, derive actual model bytes, run fresh concrete replay and assert exact fork/target/trace match; mutate byte, source, dynamic visit and target to prove downgrade. Test unsupported runtime stream, stub, under-constrained memory, solver SAT without model, solver timeout and replay error all produce non-verified status. Preserve candidate artifact/verification evidence over restart.
3. **Local coordinator, 1/2/4 workers.** Independent bounded enumerator for branch/loop/convergence fixtures; compare sorted accepted work/path IDs, dispositions and cumulative evidence across schedules and restarts. Kill workers/coordinator mid-result and mid-split, delay stale submissions, force conflicting claims, and verify fencing/idempotency, no lost/duplicate accepted paths, and no premature closure. Record throughput, replay time, memory, disk and solver cost against one worker; no scaling claim without measurements.
4. **Real Lua objectives.** Compare observational v1 behavior unchanged with v2 deterministic queued ranking across resume and worker counts, find hit, explicit exclusion vs deprioritization, ties/unknown distance, altered policy digest, invalid/changed table and unsupported artifact rejection. Report cumulative target hit evidence, not just latest `advance`.
5. **Authenticated versioned transport and host-native binaries.** Loopback and multi-process tests for bad/missing auth, version/build/binary mismatch, oversized/partial/truncated frames, malformed lengths, replayed request ID, stale fence, reconnect and partition. Repeat 1/2/4-worker result equality over TCP on one PC, then checksum-pinned native builds on multiple hosts. Compare unique accepted verified work and edges under identical limits against best single host. Keep local fallback if networking is unavailable.

Each gate fails closed: no failed or unknown outcome becomes terminal, no uncommitted evidence becomes accepted, no hash-only witness becomes verified, no stale worker result becomes accepted, and no missing artifact/semantic pin becomes a resumed campaign. Existing `docs/design/sustained-exploration-verification.md:17-24` states what the initial tests did **not** prove; do not roll those limitations into a completion claim. Documentation checks validate this plan's links and scope, not the executable gates.
