# Sustained exploration: independent adversarial verification

Scope: current shared checkout, native x86-64 ELF64 via GNU `as`/`ld`, local durable ledger, Lua API, loopback coordinator/worker processes, and a bounded three-host SSH-tunneled campaign. This is **bounded verification of finite fixtures**, not whole-program completeness, solver soundness for arbitrary binaries, or a general three-host deployment/performance result. PASS means the named check ran successfully; historical FAIL describes an earlier executed check superseded by a later PASS; NOT_TESTED is not a PASS. The historical compile BLOCKED result is neither a current FAIL nor a full runtime-suite PASS.

## Ledger scale and recovery evidence

    The recorded [ignored release fixture](../../crates/angryier-ledger/tests/sustained_wal.rs) reopened 20,003 work units and 10,001 accepted events in approximately 0.675 s. This times reopen after 10,001 splits, not symbolic execution, maximum-capacity recovery, or distributed throughput. To repeat it: `cargo test --locked -p angryier-ledger --release --test sustained_wal scale_test_10001_records_and_events -- --ignored --exact --nocapture`.

    The ceilings are 65,536 work units and 65,536 accepted events, with at most 1 GiB for checkpoint plus WAL. The JSONL projection has a separate 64 MiB limit. [Recovery](../../crates/angryier-ledger/src/wal.rs) reads the bounded WAL into memory. Durability depends on successful fsync and storage honoring it; a damaged final length with no later valid frame can look exactly like an incomplete append. Complete checksum-invalid frames are rejected. These fixtures establish neither exhaustive whole-binary coverage nor a live Windows witness: the raw Advisor GUI run yielded zero verified witnesses.

- The scripted `Answers` solver (`crates/angryier-runtime/tests/sustained_verification.rs:125-151`) tests accounting, **not** SAT or model soundness. Native-Z3 tests cover finite feasible/infeasible edges, not arbitrary binaries. The 65-decision runtime case is history retention, not a 65-deep root-replay campaign; the 4,100-step case tests concrete trace offsets, not a late symbolic branch visit ordinal. Zero-duration timeout is deterministic fail-closed accounting, not mid-query deadline enforcement.
- The process fixture has only **two active first-generation children even with four configured workers** (`crates/angryier-campaign/tests/coordinator_worker.rs:220-263`); no four-way simultaneous saturation, throughput or speedup is established. Coordinator independently recomputes every remote result with a fresh local root/solver (`crates/angryier-runtime/src/sustained_pool.rs:649-670`), so process equality is not a performance benchmark. Each worker enforces configured per-path mapped-state/trace RAM, step, solver, wall, loop/depth and trace limits, not a measured OS-level per-process RSS cap (`crates/angryier-runtime/src/sustained_pool.rs:200-231`). Pool wire format cannot durably prove an infeasible child, and remote result codec rejects unrepresentable evidence rather than claiming a complete scope (`crates/angryier-runtime/src/sustained_pool.rs:118-127,667-669`).
- Lua v2 exclusion applies only to exact dynamic branch-target proof bounds; arbitrary avoid reachability is **NOT TESTED**. Named input/stub replay and arbitrary custom Lua scripts remain unsupported (`crates/angryier-runtime/src/script/prepared.rs`). Forced I/O failures, multi-worker merge stress, and long-running cluster completeness are **NOT TESTED**.
