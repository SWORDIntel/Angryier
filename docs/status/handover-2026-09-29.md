## 3. Pipeline map (decode → execute)

```
XED bytes ──► DecodedInstruction (form_id = XED iclass!)
      ──► form_map::map_form (runtime) ──► engine form id
      ──► SemanticProvider::emit ──► SemanticOp ops (sealed block)
      ──► BasicSemanticLowerer ──► IrBlock (IrPrimitive ops)
      ──► ConcreteInterpreter / symbolic evaluator
```

## 4. The ISA-slice recipe (VNNI slice is the clean template)

1. Assemble real encodings (`as`/`objdump`) — never guess operand order.
2. Export new `XED_ICLASS_*` consts in `angryier-arch-xed-ffi`.
3. Add form ids (EVEX-encoded insns → `avx512::forms`/`evex_forms`,
   next free block — VNNI used `0x1140..0x1157`; others → root `forms`).
4. If the semantics need a new vector op: `VectorOp` variant →
   `block.rs` serializer byte (next: 47) → `IrPrimitive::Vec*` →
   `lower.rs` arm → `interpreter.rs` eval arm (byte-oriented, see §5).
5. Write the provider macro + instantiate per form; rule id = form +
   `0x500` offset convention (VNNI: `0x1640..0x1657` → ids `0x2640..`).
6. Register: `providers()` list **and** `registry.rs::ALL_FORMS` (bump
   the array size — currently `1404`).
7. `form_map.rs`: match arms keyed on operand-shape arrays.
8. Tests: encoding assertions in `form_map.rs` test module; engine test
   in `avx512_engine.rs` (append provider+form to the parallel
   `providers`/`all_forms` lists — they are index-aligned).

## 5. Invariants and footguns

- **`form_id` is the XED iclass at decode time**, not the semantic form.
  Semantic form ids are assigned by `form_map`. Do not conflate them.
- **Two form namespaces**: `forms` (root) vs `evex_forms`
  (`avx512::forms` re-export). Match form ids to the right namespace in
  `form_map.rs`.
- **EVEX reports the opmask as an explicit `Reg64` operand** at index 1:
  `[dst, k, src1, src2]`. `evex_source_indices(insn)` returns `(2,3)` for
  ≥4 operands, `(1,2)` otherwise — reuse it.
- **Masking is fully wired**: EVEX opmask (merging and zeroing) is extracted
  from XED modifiers and applied across all EVEX providers (packed float/double,
  scalar float/double, logic, VNNI) via `apply_evex_mask` with `VectorOp::MaskMerge`
  and `VectorOp::MaskZero`.
- **Lane-wise ops are 128-bit-limited**: `VecLane*`/`Madd16`/`DotU8S8`/`DotS8S8`/`DotS8U8`
  eval on `u128`. For YMM/ZMM, providers must decompose to per-128-bit
  slices via `Extract`/`Concat` — the `packed_float_zmm` and `vnni_dot`
  macros show the pattern. Emitting a 256/512-bit `LaneWise` op will
  panic the interpreter with shift overflow.
- **Concrete values >128 bits are byte arrays** (`bytes_le`), not u128.
  New `IrPrimitive` eval arms must use `bytes_le()` +
  `ConcreteValue::from_bytes_le` like the existing `bytes_*` helpers.
- **Symbolic side has no vector coverage**: `eval_primitive_concrete`
  returns `None` for unlisted prims → ops are refused explicitly. New
  Vec prims only need the concrete arm.
- **Rule-id band**: `avx512_engine.rs::test_registry_and_rule_id_conformance`
  asserts ids in `0x2600..0x2680` and provider count (108) — update both
  when adding providers.
- **`providers()` order = `all_forms[]` order** in the engine test —
  append to both in identical order.
- Opmask K-ops decode: word ops are VEX2 (`c5 .. 4x`), qword ops VEX3 W=1
  (`c4 e1 .. 4x`) — shapes `[Reg64;3]`/`[Reg64;2]`.

### APX slice notes (landed 2026-09-29, uncommitted)

- **Semantic contract change**: a 2-input `SideEffect::MemoryWrite` now
  lowers to a real `IrOp::Store`; empty/1-input side effects stay hints.
  `PrimitiveOp::Load` (canonical tag 39) is the value-producing computed
  load. `FarPointer` operands read as the 64-bit offset and resolve as
  absolute branch targets. Anything that emitted computed-address stores
  before (CET WRSS) now executes them.
- **Encodings (canonical, encoder-verified)**: CCMP w64 opcode `0x39`,
  cc = EVEX P2 low nibble, DFV = P1[6:3] (decodes as an immediate — the
  DFV-register→Immediate backend mapping), W = P1[7]. CTEST opcode `0x85`
  same layout. CFCMOV opcode `0x40+(cc&3)`, P2[3]=cc>>2. NF = EVEX P2 bit
  2 (`0x04`) — `62 7c fc 14 01 c9` is NDD ADD with NF, `...10...` without.
  PUSH2/PUSH2P and POP2/POP2P share explicit shapes `[Reg64,Reg64]`; the
  form-map discriminator is the suppressed stack-operand width (64 vs 128).
- **Rule band** `0x2A00..0x2A3C`, 61 providers/forms; `providers()` order
  = `ALL_FORMS` tail order (JMPABS, pairs, 16 CCMP, 16 CTEST, 10 NDD ALU,
  6 NDD shifts, 8 CFCMOV).
- **Byte pinning tool**: `crates/angryier-arch-xed-ffi/tests/apx_encode.rs`
  wraps the XED encoder (`xed_tables_init()` first — forgetting it yields
  `XED_ERROR_GENERAL_ERROR` for every request). Use it to derive canonical
  bytes for future slices instead of hand-assembling.
- **Known approximations**: CFCMOVcc is a non-faulting Select (real #UD
  on false condition not modeled); CCMP/CTEST/CFCMOV/NDD landed r64-only
  (w32 EVEX decodes fall to the unmapped catch-all).
